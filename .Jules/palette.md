## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.
## 2025-03-04 - Keyboard Accessibility for Custom Checkboxes and List Items
**Learning:** Using `display: none` on native `<input type="checkbox">` elements completely removes them from the accessibility tree, making them invisible to screen readers and impossible to focus via keyboard. Relying solely on `@click` for custom `<p role="button">` elements also excludes keyboard users.
**Action:** When styling custom checkboxes with Tailwind, always use the `sr-only` class on the native `<input>` combined with the `peer` class, and style a sibling element using `peer-focus-visible` for focus rings. For custom interactive elements (like `role="button"`), always add `tabindex="0"` and bind both `@keydown.enter.prevent` and `@keydown.space.prevent` alongside standard click handlers to ensure full keyboard interactivity. Use `group-focus-within` to reveal hover-only actions to keyboard users.
