## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.
## 2025-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** When building custom interactive elements that act like buttons (e.g., a `<p role="button">`), they must include `tabindex="0"` and handle `@keydown.enter` and `@keydown.space.prevent` events to be fully keyboard accessible. Furthermore, relying solely on hover utility classes (e.g., `group-hover:opacity-100`) hides elements from keyboard users; always pair them with `focus-within:opacity-100` or similar focus states. When hiding native `<input>` elements for custom styling, avoid `display: none` as it breaks keyboard accessibility and screen reader perception. Instead, hide them visually using absolute positioning, zero opacity, and 1px dimensions while styling the focus state of a sibling element.
