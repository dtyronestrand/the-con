## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.

## 2026-09-22 - Keyboard Accessibility for Custom Checkboxes and List Actions
**Learning:** Using `display: none` on native inputs for custom checkboxes completely removes them from the accessibility tree, making them unfocusable via keyboard. Furthermore, list items acting as custom interactive elements (like a task title acting as a button) require explicit keyboard event handlers (`@keydown.enter`, `@keydown.space`) and `tabindex` to function correctly for keyboard users. Relying only on `group-hover` for revealing actions hides them from non-mouse users.
**Action:** When styling custom checkboxes, replace `display: none` with Tailwind's `sr-only` class to keep the native input focusable. Use `peer` and `peer-focus-visible` to style sibling elements (like a custom checkmark) when the native input receives focus. Add `tabindex="0"` and keyboard equivalents for all `@click` events on non-semantic elements acting as buttons. Use `group-focus-within` in combination with `group-hover` to reveal hidden actions via keyboard navigation.
