## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.
## 2024-05-14 - Interactive Elements Focus and Keyboard Handling
**Learning:** In Vue, native DOM elements with `role="button"` (like `<p role="button">`) require `tabindex="0"` and explicit keydown handlers (`@keydown.enter`, `@keydown.space.prevent`) to be functionally accessible to keyboard users. Additionally, relying solely on `group-hover` utility classes hides elements from keyboard focus entirely; they must be paired with `group-focus-within` or explicit `focus-visible` styling to ensure perceivability.
**Action:** Always test interactive elements without a mouse. When using custom DOM elements as buttons, immediately add `tabindex="0"` and the required key handlers. When conditionally hiding UI elements (like edit/delete actions) until hovered, immediately pair the hover state with `focus-within` or `focus-visible` styles.
