## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.
## 2026-10-06 - Task list keyboard accessibility & UX improvements
**Learning:** Custom checkboxes implementing `display: none` on the native input completely break keyboard tabbing and accessibility tree integration. Furthermore, list items mimicking buttons (`role="button"`) without explicit `tabindex="0"` and mapped `@keydown.enter/space` handlers strand keyboard-only users, preventing them from accessing modals or contextual actions.
**Action:** When styling custom checkboxes, always use Tailwind's `sr-only` (Screen Reader Only) utility combined with the `peer` class on the native input, and style a sibling element using `peer-focus-visible`. For custom elements acting as buttons, explicitly add `tabindex="0"` and map keydown events for Enter and Space to ensure full interactive parity.
