## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.

## 2024-10-16 - Custom Checkbox and Group Hover Accessibility
**Learning:** Using `display: none` on a native `<input type="checkbox">` completely removes it from the accessibility tree, making custom styled checkboxes inaccessible to keyboard navigation and screen readers. Additionally, when using `group-hover` to reveal interactive elements (like the checkmark), keyboard users are left out if there isn't a corresponding focus state.
**Action:** Use `.sr-only` class (or similar visually-hidden techniques) instead of `display: none` for native inputs to keep them focusable. Style custom siblings using Tailwind's `peer` and `peer-focus-visible` classes. Always pair `group-hover:opacity-100` with `group-focus-within:opacity-100` on parent containers to ensure revealed elements are accessible via keyboard navigation.
