## 2024-05-14 - Keyboard Accessibility in Interactive Elements
**Learning:** Relying solely on `group-hover:opacity-100` to show interactive elements hides them from keyboard users who cannot hover. Additionally, icon-only buttons need `aria-label` and `title` attributes to be perceivable by screen reader users and to display tooltips.
**Action:** When adding hover states that reveal actionable elements, ensure there is a corresponding `focus-within:opacity-100` state. Always use accessible names (`aria-label`, `title`) and clear `focus-visible` styling on icon-only buttons.

## 2025-03-05 - Keyboard Accessibility in Custom Inputs and Buttons
**Learning:** When building custom interactive elements that act like buttons (e.g., a `<p role="button">`), ensure they are fully keyboard accessible by including `tabindex="0"` and handling `@keydown.enter` and `@keydown.space.prevent` events. Also, when styling custom form inputs (like checkboxes), do not use `display: none` on the native `<input>` as it breaks keyboard accessibility. Instead, hide it visually (e.g., `opacity: 0; position: absolute; width: 1px; height: 1px;`) and style a sibling element using `:focus-visible` for keyboard focus rings.
**Action:** Always visually hide rather than use `display: none` for native inputs that back custom UI elements. Always provide `tabindex="0"` and keyboard handlers for custom button-like tags.
